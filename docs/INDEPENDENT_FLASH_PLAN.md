# 独立烧录后端分阶段设计

本文只描述接口边界，不代表当前已经具备 STC32 写入能力。

## 当前可用层

### 1. 只读查询

输入：串口和用户手动按下 RES。

输出：型号、Magic、BSL 版本、频率、参考电压、原始状态 payload。

约束：不得发送擦除、写程序、写硬件选项或调频命令；硬件选项和 EEPROM 映射标记为未验证。

### 2. 离线准备

输入：本地 Intel HEX。

输出：格式/校验和/地址范围检查、稀疏分块摘要、SHA-256。

约束：分块是审查数据，不是 STC ISP 写包；不会打开串口。

## 历史设计门槛（0.1.1 及更早版本）

0.1.2 已完成 STC32G12K128 的实机验证；以下内容保留用于说明此前的安全门槛，不代表当前插件仍禁用烧录。

### 3. 实机协议验证

需要在专用测试板和可恢复固件上确认：

- 握手、擦除、写入、ACK/错误码；
- STC32G12K128 的地址范围与 128 KiB 跨区规则；
- 写后回读或校验命令；
- RES 时序、超时、中止和断线恢复；
- 固件版本变化（当前板为 BSL 7.4.5U）。

这一层只能先做测试后端，默认拒绝真实写入。

### 4. 真实写入

只有当第 3 层证据完整，并经过独立审查后，才允许设计写入命令。默认策略仍应是：

- 明确显示芯片、串口、HEX 摘要；
- 明确确认是否擦除；
- 默认不写 EEPROM 和硬件选项；
- 每个阶段都有超时和可中止状态；
- 写入结束必须有设备端确认；
- 未通过校验时报告失败，不得伪造成功。

任何新增代码都不得通过隐藏设置、环境变量或命令行参数绕过上述禁用状态。

## 方案 B 的当前实现方式

方案 B 表示未来可显式选择“允许擦除 EEPROM”和“允许写入硬件选项”，以匹配官方 STC-ISP 的工作习惯。
这两个设置目前默认关闭；即使用户打开，它们也只会出现在安全检查摘要中，不会启用真实写入。
只有在 STC32 写包、保留位、ACK 和回读协议完成实机验证后，设置才可能连接到受控写入流程。
